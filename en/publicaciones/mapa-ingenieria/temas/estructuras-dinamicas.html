    Dynamic data structures

    When you do not know in advance how much data is going to arrive, the array gets in the way. The linked list grows and shrinks by following pointers, and with that mechanism you build queues, stacks and trees.

    Linked list Nodes Stack Queue Binary tree

    01When the array is not enough

    An array is fast and simple, but its size is fixed, decided before the program runs. If more data arrives than expected, it overflows; if less arrives, memory is wasted. A dynamic structure grows and shrinks during execution, allocating one node per item of data.

    OperationArrayLinked list
    Access element iO(1): direct calculationO(n): you have to traverse
    Insert at the beginningO(n): shift everythingO(1): change two pointers
    Insert at the endO(1) if there is roomO(n), or O(1) with a pointer to the tail
    Delete from the middleO(n): shift everythingO(1) if you already have the previous node
    Memory per itemOnly the dataThe data plus a pointer
    Cache localityExcellent: contiguousPoor: scattered nodes
    Which one to choose

    There is no winner: there is judgment. If you know the size and access by index, use an array. If there are many insertions and deletions at arbitrary positions, use a list. And in practice, for a few elements the array often wins anyway, because contiguous memory flies in the processor’s cache.

    02The linked list

    Each node holds the data and the address of the next one. The last one points to NULL, and an external variable —the head— holds the address of the first:

    typedef struct node {
        int data;
        struct node *next;
    } Node;

    Node *head = NULL;

    The structure refers to itself: that is why the name struct node is needed inside its own definition. Inserting at the beginning takes three lines:

    Node *n = malloc(sizeof(Node));
    n->data = x;
    n->next = head;
    head = n;
    Order matters

    If you do head = n before n->next = head, the node points to itself and the whole list is lost. In linked structures, the order of pointer assignments is the most frequent error and the hardest to spot by reading.

    The stack you have already been using

    Each function call pushes its frame —local variables and return address— and pops it on return. That is why a recursion without a base case ends in a stack overflow: the data structure that overflows is, literally, a stack.

    04Binary trees

    In a binary search tree, everything smaller than a node is in its left subtree and everything larger is in the right one. Searching means walking down comparing, and if the tree is balanced each comparison discards half of the remaining data: 20 comparisons are enough for a million elements.

    • In-order traversal —left, node, right— returns the data sorted from smallest to largest.
    • Preorder —node, left, right— is used to copy the structure.
    • Postorder —left, right, node— to free it, because it destroys the children before the parent.

    The problem is imbalance: if the data arrives already sorted, the tree degenerates into a list and search goes back to O(n). This is the origin of self-balancing trees, such as AVL and red-black trees.

    05Where they are used in a device

    • UART circular buffer. The receive interrupt writes to the queue and the main program reads: it is the most widely used structure in embedded systems.
    • Event queue. A graphical interface, a real-time operating system and firmware with a state machine all use the same producer-consumer scheme.
    • A scheduler’s task list. Ordered by priority or by deadline.
    • Sample history. A sliding window for averaging or filtering signals is implemented with a circular queue.
    • Device table. An operating system kernel maintains linked lists of open processes, files and drivers.

    07Common mistakes

    • Losing the head of the list by reassigning pointers in the wrong order.
    • Freeing a node before saving its next, and being left with no way to reach the rest.
    • Not handling the empty list or the deletion of the first node, which are the two edge cases.
    • Forgetting to set the next of the last node to NULL.
    • Using a list where an array was the better choice, only because it sounds more sophisticated.
    • Traversing with the same pointer that is used to free, without an auxiliary variable.

    08Self-assessment

    How much does it cost to insert at the beginning of a linked list?

    O(1): allocate the node and change two pointers, no matter how many elements there are.

    Why is accessing element 500 of a list slow?

    Because you have to follow 500 pointers: the address cannot be calculated, you have to traverse.

    Which structure suits a UART’s receive buffer?

    A circular queue on a fixed array: it needs no malloc, its size is known and an interrupt can use it safely.

    Which traversal of a binary search tree returns the data in order?

    The in-order traversal: left, node, right.

    What happens if already sorted data is inserted into a simple binary tree?

    It degenerates into a list: each node has only one child and the search goes from O(log n) to O(n).

    Why does infinite recursion end in a “stack overflow”?

    Because each call pushes a frame with its local variables, and the program’s stack has a limited size.
